# 数据说明

## 来源

当前比赛结果来自**英文维基百科**的赛季页面和各站赛事页面，通过维基百科的公开接口（MediaWiki API）下载。尚未导入 snooker.org、CueTracker 的实时数据。已提供可选的 snooker.org 接入工具，授权、映射和核对流程见下文；映射表目前为空。

覆盖范围：2023/24、2024/25、2025/26、2026/27（进行中）四个赛季，世界职业斯诺克巡回赛（WST）日历上的赛事，包括排名赛、邀请赛、各站资格赛和冠军联赛。不收录：单局赛 Shoot Out、混双、国家杯、六红球、元老赛、女子赛、世界杯、Q School、21 岁以下赛事。

## 文件

### `data/matches.csv`：每行一场比赛

| 字段 | 含义 | 例子 |
|---|---|---|
| `date` | 比赛日期（规则见下文"日期"一节） | 2026-11-03 |
| `event` | 赛事，维基百科页面标题；资格赛并入所属赛事 | 2026 International Championship |
| `country` | 赛事举办国 | China |
| `p1`、`p2` | 两位球员，用维基百科条目名（去掉"(snooker player)"后缀） | Stephen Maguire、Ding Junhui |
| `f1`、`f2` | 两人各赢的局数 | 5、6 |
| `nat1`、`nat2` | 两人的国籍代码（取自页面上的国旗模板，个别球员缺失） | SCO、CHN |

当前数据量、日期范围及回测统计统一见 [自动生成的评估报告](../evaluations/summary.md)，输入文件的校验值见 [manifest.json](../evaluations/manifest.json)。

`stage` 列标记 `main` / `qualifying`，资格赛独立页面和资格赛章节均标记为 `qualifying`。

`data/centuries.csv` 保存各赛事破百，`data/history/` 保存历史统计；预测只读取顶层 `matches.csv` 和 `events.csv`。

### `data/events.csv`：每行一站赛事

| 字段 | 含义 |
|---|---|
| `event` | 赛事页面标题，和 matches.csv 的 `event` 对应 |
| `start_date`、`end_date` | 正赛的开赛日和结束日，取自赛季页面的赛历表 |
| `country` | 举办国 |

回测按 `start_date` 划分"赛前"和"赛后"。

### `data/names_zh.json`：中文名

`{"英文 ID": "中文名"}`。写法以大陆媒体的通行译名为准，例如斯佳辉、侯赛因·瓦菲、王信伯。每个名字都在网易、新浪、搜狐的赛程战报或百度百科上核实过，各家写法不一致时以百度百科为准；不用中文维基，因为很多球员没有条目，有的是港台译名。模型本身不读这个文件，只是方便中文读者对照。

### `data/names_zh_sources.json`：中文名的出处

`{"英文 ID": {"zh": 中文名, "checked": 核实日期, "sources": [网址, ...], "note": 说明}}`，记录每个中文名是在哪几篇报道或词条上核实的。2026-11-03 起新加的名字都有记录；更早加入的 23 位常见球员（丁俊晖、特鲁姆普等）当时没有逐条记网址。新加名字时，名字和出处一起提交。

## 怎么生成的

```bash
python3 src/fetch_wiki.py raw 2023-24 2024-25 2025-26 2026-27   # 下载，需要先 mkdir raw
python3 src/parse_matches.py raw data                           # 解析，生成 data/matches.csv 和 data/events.csv
```

1. `fetch_wiki.py` 先下载每个赛季的页面（如"2025–26 snooker season"），从"World Snooker Tour"一节的赛历表里找出每站赛事的链接，再下载每站赛事的页面，以及"<赛事> qualifying"资格赛页面（存在的话）。同时记下每个页面的最后修订时间。
2. `parse_matches.py` 从页面的维基代码里认出三种写法的比分：
   - 签表模板（比如 16 强到决赛的对阵图），包括带参数名和按位置排列的两种写法；
   - 列表写法，例如"* A 6–4 B"，资格赛和冠军联赛多用这种；
   - 单独的决赛表：很多页面的签表只画到半决赛，决赛另起一张表（表头写"'''Final:''' Best of 19 frames"，下一行是"球员 | 比分 | 球员"）。

### 抓取与映射

在运行环境设置 `SNOOKER_ORG_REQUESTED_BY`，值使用站方批准的内容，不写进代码或 Git。
未设置时脚本会在发出请求前退出；401/403 不重试，也不尝试其他身份。
每次请求间隔至少一秒，网络错误、429 和服务端错误最多尝试三次；单次请求超时 30 秒。
有进一步限流要求时，使用 `--interval 秒数` 增大间隔。

```bash
# 以下命令从模型仓库根目录执行；2023 表示 2023/24 赛季。
# 先获取赛事目录，查看 ID、Name、Main、Stage、日期等字段。
python3 -I src/fetch_snooker_org.py raw/snooker_org_catalog.json 2023 2024 2025 2026 --catalog-only

# 确认授权用途和所需赛事后，抓取结果、轮次与球员。
python3 -I src/fetch_snooker_org.py raw/snooker_org_snapshot.json 2023 2024 2025 2026
# 可加 --events ID1 ID2，仅验证指定赛事。
```

快照保留请求 URL、抓取时间和未经改写的 API 记录，不保存授权请求头。
同名快照禁止覆盖，刷新时换一个带日期的新文件名。

编辑 `data/snooker_org_mapping.json`：`events` 的键是 API 赛事 ID，值为
`{"event": "matches.csv 中已有的赛事名", "stage": "main 或 qualifying"}`；
`players` 的键是 API 球员 ID，值为已有的英文球员名，用于明确处理名字不一致。
资格赛、正赛和冠军联赛小组可能分别有 ID，必须逐一映射；不会自动按近似赛事名称合并。
姓名匹配沿用项目已有归一化规则，尝试姓名正序和姓在前的顺序，不使用模糊匹配。
不同球员 ID 被解析为同一个本地名字时，会报告冲突。

### 审计与应用

```bash
# 默认只生成逐行变化与冲突报告，matches.csv 不变。
python3 -I src/enrich_snooker_org.py raw/snooker_org_snapshot.json data data/snooker_org_mapping.json --report output/snooker_org_audit.json

# 核对报告后应用；只要存在冲突，就拒绝整次写入。
python3 -I src/enrich_snooker_org.py raw/snooker_org_snapshot.json data data/snooker_org_mapping.json --report output/snooker_org_audit.json --apply
python3 -I src/evaluate.py
python3 -I src/evaluate.py --check
```

合并必须同时匹配已映射的赛事、阶段、球员和比分，允许球员左右顺序颠倒。
遇到同一对球员同比分的重复场次，初次合并不会按列表顺序或维基近似日期猜测。
未完成、退赛、团体赛、排名用的冠军占位记录均不导入。
没有映射的赛事、库中不存在的比赛会统计为跳过，不新增行。
应检查 `matched_rows/local_rows`、`unmapped_event_ids`、`skipped` 和 `issues`，不能将部分匹配当作全覆盖。

新增列：

| 列 | 含义 |
|---|---|
| `date_wikipedia` | 合并前的维基日期，保留用于追溯 |
| `date_source` | `wikipedia` 或 `snooker.org:EndDate:UTC` |
| `snooker_org_key` | `EventID:Round:Number`；不用会随修改变化的 API `ID` |
| `snooker_org_event_id` | 来源赛事 ID |
| `snooker_org_p1_id`、`snooker_org_p2_id` | 对应本地 p1、p2 的来源球员 ID |
| `snooker_org_round`、`snooker_org_round_name` | 原始轮次编号、赛事轮次名称 |
| `snooker_org_scheduled_at`、`snooker_org_started_at`、`snooker_org_ended_at` | API 原始计划、开始、结束时间 |
| `snooker_org_estimated` | 计划时间是否为估计值 |
| `snooker_org_source_url`、`snooker_org_fetched_at` | 原始比赛接口和快照时间 |

只有已结束且通过时间检查的比赛，才用 `EndDate` 的 **UTC 日期**更新模型的 `date`。
跨日比赛用完成日期；缺少带时区的结束时间时保留维基日期，不能拿计划／开始／修改时间替代。
未来结束时间、早于开始时间或明显超出赛事日期范围会阻止应用。
模型仍按天截断，尚不支持精确到时分的预测截止时间；资格赛即使延后至正赛期间，也不纳入正赛回测测试集。
结束时间来自事后快照，不能当作数据当时已公开的证明；复现历史预测仍需保存当时的快照。

重新运行维基解析会重建 `matches.csv` 并移除补充列；因此每次更新按“维基解析 → 来源合并 → 回测”运行。
正式运行前先解决授权与赛事映射；当前空映射只会报告未映射赛事，不会宣称已完成接入。

## 处理规则

**日期**。维基百科的签表里没有逐场日期，所以：

- 正赛的日期取"赛事结束日"和"页面最后修订日"里**较早**的那个。赛事还没打完时，已经打完的场次就记成抓取当天；模型按截止日期取数据时，这些比赛不会被漏掉。
- 资格赛从资格赛章节或提到 qualifying 的句子读取日期区间最后一天，读不到时回退到正赛结束日。
- 冠军联赛按每个小组页面上写的比赛日期记（例如"Group 5 was played on 19 and 20 January 2026"，有按天的四级标题就按天），不统一记成整站的结束日。否则 1 月初打的小组赛会被当成 2 月才打。

这意味着同一站正赛的所有比赛共用一个日期。当前快照可用于随后发布的预测；但不能用更新后的文件还原同一赛事早先的赛前状态，也不能用它研究赛事内部的先后顺序。复现历史预测须使用当时的 Git 提交或迁移前归档。

**去重**。同一个页面上，同一对球员、同一个比分出现两次，通常是同一场比赛列了两遍（比如签表里一次、决赛段落里一次），只算一场。冠军联赛例外：同一对球员可能在后面的小组再次相遇，而且比分相同，所以只在同一个小组内部去重。决赛表只作补充：签表里已经有这场决赛就不再计入；冠军联赛只认签表里的附加赛，不认小组循环赛里同比分的那场。

**不计入的比赛**：弃权（w/o、w/d、退赛）、0:0、比分不是数字的场次，以及轮空。

**球员身份**。同一个人在不同页面可能写成"Ross Muir (snooker player)"和"Ross Muir"，或者大小写不同，统一合并成一个 ID。冠军联赛的列表里有些名字没有链接，会按其他页面里同名的链接对上。国籍取这位球员在所有页面上出现最多的国旗。

## 核对过什么

- 每站赛事信息框里的冠军和亚军，都能在 matches.csv 里找到这场决赛（2026-11-04 核对 73 站，全部吻合）。
- 每站的场数是否合理：128 人签表的排名赛约 120 场以上。
- 有没有同一个人被拆成两个 ID。
- 随机抽查已知赛果。

## 已知问题

- 维基百科页面是志愿者编辑的，个别比分可能填错或晚更新；正在进行的赛事，抓取时页面可能还没更新完。
- 页面写法变了（新的模板、新的表格格式），解析器可能漏掉一部分比赛。找到决赛表却读不出比分时，脚本会打印警告。
- 部分球员缺国籍代码。模型只在主场项里用到国籍，默认不用主场项，所以不影响结果。
